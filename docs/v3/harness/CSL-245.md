# CSL-245 — provider-free end-to-end turn profile (W1)

Date: 2026-10-17. Parent issue: CSL-245. Parent goal: CSL-240.

Scope authority is Lucas's confirmation recorded in Linear comment
32f2e0f3 (2026-10-16). W1 is the bake-off's shared workload: spawn, first
event, parse, validate, persist. This profile establishes a baseline. It
does not set a numeric budget.

No provider CLI is started. The replay child is
`[sys.executable, "-X", "utf8", "-B", "-c", <script>]`. The script writes
the LF-normalised fixture to stdout, one line at a time, and flushes.
`HeadlessCLI.execute` runs that child through its injected `runner`. The
provider argv is not executed. `perf_bench.install_network_guard()` refuses
socket connects.

## What W1 measures

Each turn is timed with `time.perf_counter_ns()`:

| Phase | Clock |
|---|---|
| spawn | `Popen` call to its return |
| first_event | that return to the first non-empty stdout line |
| stream_parse | `assistant_text`, `claude_last_message`, `parse_usage`, `add_usage`, `parse_verdict` |
| validate | `call_fits` and `exceeded` against `default_budgets()`, and the approve/revise token |
| persist | `save_run` into a `tempfile.TemporaryDirectory` |
| total | start of the turn through persist |

Reading the rest of stdout sits between first_event and stream_parse, so the
named phases sum to at most total. A trivial child that prints one line and
exits is the baseline row. Harness overhead is the fixture's total median
minus that row's spawn median. Both operands are in the report.

p99 is null when n < 100. RSS is `resource.getrusage` on POSIX and null on
Windows, where that module is not in the stdlib. Child CPU time is the
`os.times` children fields. No extra package is imported.

## How to run

Smoke (3 turns, no pilot) is what the required linux job runs, via
`tools/test_perf_e2e.py`:

```
python -X utf8 -B tools/perf_e2e.py --smoke --out /tmp/e2e.json
python -X utf8 -B tools/perf_e2e.py --fixtures claude-stream-json,grok-review --smoke
```

The pilot is not a per-PR gate. It takes 5 turns, freezes
`N = ceil(4·Z²·σ²/W²)` with σ = stdev/mean, Z = 1.96 and W = 0.05, then
stops at that N or at the agent-proposed cap (30 turns or 20 s per fixture).
Relative IQR above the agent-proposed 0.25 after the cap marks the row
`unstable`. The process still exits 0. It exits non-zero only for a missing
or modified fixture digest, a parser exception, a network attempt, or a
child failure.

```
python -X utf8 -B tools/perf_e2e.py --out /tmp/e2e.json
```

## Preregistration

`tools/perf_e2e.workload.json` (schema `recursion-perf-e2e-workload/1`)
freezes the five CSL-84 stream fixtures, their LF-normalised SHA-256, and
the evidence class from each fixture header. Those files have `eol`
unspecified. A Windows autocrlf checkout stores CRLF, which is the CSL-225
failure mode, so the digest hashes LF-normalised bytes. `.gitattributes`
was not edited.

Host profiles copy the D-028 floors for Linux x64 and Windows 11 x64.
macOS ARM is listed as not a support commitment. Every host has
`measured: false`.

pyperf 2.10.0 uses the same sample-size shape with W = 0.01. This file
uses W = 0.05 because that is the W1 rule. The cap and the 0.25 relative
IQR bound are agent-proposed. Lucas can amend the `proposed_by_agent` block.

## Twelve PERFORMANCE-PLAN dimensions

| Dimension | Observable provider-free | Null reason |
|---|---|---|
| authority, safety, privacy, effects | no | Provider-free fixture replay does not issue an effect, check isolation, or record a policy decision. |
| verified quality | no | No accepted-gate result, escaped defect, or verifier disagreement is produced. |
| recovery and replay | no | The frozen stream is parsed once. This is not a restart, a reconciliation, or a replay-parity check against a live session. |
| owner/operator cost | no | No review minutes, intervention count, or comprehension probe is collected. |
| quota, tokens and money | no | Fixture usage fields are not a provider-reported account window or a metered receipt. Unavailable is not zero. |
| context/cache efficiency | no | No cache read, write, invalidation, or fidelity miss is observed. A cached_input_tokens field in a fixture is not a measurement. |
| latency and throughput | yes | Phase medians are the observation. Input, append, and recovery latency, accepted throughput, and p99 before n ≥ 100 stay null. |
| host resources | yes | Child CPU time, and RSS on POSIX. Disk, I/O, network bytes, wakeups, and handles stay null. RSS is null on Windows. |
| terminal interaction | no | No frame, input, flicker, Unicode, or accessibility observation is taken. |
| portability/configurability | no | Host floors are listed with measured false. One runner does not establish a platform matrix or a fail-closed unknown. |
| code and maintenance surface | no | Privileged code, dependency set, binary size, and defect density are not measured. |
| extensibility/idle cost | no | No plugin or disabled-path import, read, process, or call is measured. |

## What this does not prove

- No numeric budget. The illustrative p95 thresholds in the issue are not approved.
- The fixtures are synthetic or source-documented. They are not a live capture from this run.
- A CI runner is a noisy host. `unstable` means the capped sample did not settle. It is not a product failure.
- D-028 host floors are unmeasured. macOS ARM is not a support commitment.
- Smoke on the required linux job checks the harness path. It is not the tier-2 baseline. That run belongs on dispatch, `ci:full`, or nightly, which is a workflow and spend decision.
